# 08 非功能需求与技术亮点

## 1. 非功能需求

### 1.1 性能目标
- 文章详情接口：缓存命中后 P95 < 200ms
- 文章列表接口：P95 < 300ms
- 搜索接口：P95 < 500ms
- 发布文章：主请求只写 MySQL，不等待通知与热度副作用

### 1.2 可用性目标
- Redis 故障时允许回源数据库（`ArticleCacheManager` 缓存未命中走 MySQL）
- 监听器内部异常不应回滚主事务（监听器内部 try-catch）
- 关键路径（详情 / 列表）任何异常都不应让接口 500

### 1.3 安全要求
- JWT 鉴权（accessToken + refreshToken）
- Token 黑名单（Redis 存储）
- Refresh Token 与用户绑定（Redis 存储）
- 评论 / 关注 / 点赞限流（**未实现，预留**）
- 密码 BCrypt
- 上传文件类型限制（jpg/png/gif/webp，最大 5MB，登录用户）

### 1.4 可维护性要求
- 模块化目录（`pureblog-xxx`）
- 统一响应 `ApiResponse<T>` / `PageResult<T>`
- 统一异常 `BusinessException` + `ErrorCode`
- 统一日志（logback-spring.xml）
- 统一事件定义（`pureblog-common` 的 `event/` 包）

## 2. 当前技术亮点

### 2.1 异步事件驱动
**亮点**：
- 文章发布后主事务只写 MySQL，副作用（通知、热度）通过 `Spring ApplicationEventPublisher` 派发
- 监听器（`NotificationEventListener` / `StatsEventListener`）解耦
- 监听器中的异常不会回滚主事务

**面试价值**：可以讲事务边界、事件分发、监听与重试。

### 2.2 MySQL 全文检索
**亮点**：
- 标题 / 摘要 / 正文 / 标签名四字段多表 JOIN 匹配
- 服务端先 HTML 转义原文再插入 `<em>` 标签（防 XSS，前端 `v-html` 渲染）
- 正文截取 ±75 字符片段，每篇文章最多 3 条
- 支持 status=PUBLISHED + deleted=0 过滤，无索引一致性问题
- LIKE 通配符按字面量处理（`ESCAPE '!'`），手写 `LIMIT/OFFSET` 分页

**面试价值**：可以讲为什么不用 ES（成本 > 收益）、XSS 防护顺序（先转义再插标签）、LIKE 通配符处理、
升级路径（MySQL `FULLTEXT` + ngram 分词器）。

> 既有 `selectPage` 未分页问题（本项目未注册 MP `PaginationInnerInterceptor`）：搜索实现刻意绕开 `selectPage`，
> 用 `SearchMapper.xml` 手写 SQL 绕开未分页的 `selectPage`。

### 2.3 Redis 多场景
**亮点**：
- 文章详情缓存（字符串，TTL 30 分钟）
- 热门 ZSet（`pureblog:article:hot:zset`，score 实时累加 + 5 分钟兜底）
- PV 计数器（`INCR`）
- UV 集合（按 `yyyy-MM-dd` 维度）
- 用户资料缓存（字符串，TTL 30 分钟）
- 验证码 / 刷新 Token / 黑名单

**面试价值**：可以讲缓存 key 设计、TTL、缓存一致性、击穿/穿透/雪崩处理。

### 2.4 一致性策略
- 写 MySQL 后删除详情缓存（Cache Aside）
- 搜索直接读主库，无索引一致性问题
- 不强求分布式事务，目标是最终一致

### 2.5 线程池与异步
- `AppConfig` 自定义 `ThreadPoolTaskExecutor`（核心 8，最大 16，队列 200）
- `@EnableAsync` + `@Async` 在监听器中显式标注
- 拒绝策略 `CallerRunsPolicy`，优雅关闭等待 60s

### 2.6 鉴权
- JWT accessToken + refreshToken 双 Token
- Refresh Token 存 Redis，可强制下线
- 退出登录通过黑名单实现（accessToken 加入 Redis）
- 过滤器：`JwtAuthenticationFilter`（注册在 Spring Security 链中）

### 2.7 仪表盘
- 实时聚合：总文章数 / 总用户数 / 总评论 / 总阅读
- 当日发布数
- 待审核评论数

### 2.8 目录树组织
**亮点**：
- 物化路径（`path`）便于子树查询与递归展开
- 文章必须挂到叶子节点（`assertIsLeaf` 在 `ArticleServiceImpl.createArticle / updateArticle` 中强校验）
- 文章计数一致性：`createArticle +1`、`deleteArticle -1`、`updateArticle` 跨节点移动 -1 +1 切换
- `pb_article.tree_id` + `pb_tree_node.tree_id` 双层关联，前台可按节点或按主表过滤

**面试价值**：可以讲物化路径的取舍、计数一致性、强校验时机。

## 3. 不建议硬秀的点

以下功能当前并未实现，面试时被问「为什么没做」建议这样回答：

- ~~Kafka 异步消息~~：当前用进程内事件已足够，没必要引入额外中间件
- ~~微服务拆分~~：单体业务闭环还没做扎实，拆服务只是把复杂度转移
- ~~MinIO 文件存储~~：当前本地 `uploads/` 足够；后续要换只需替换 `UploadController` 的存储实现
- ~~限流~~：当前单机单用户场景不构成压力，未做
- ~~链路追踪~~：单体阶段 APM 收益有限
- ~~RBAC 角色权限矩阵~~：单一作者，admin 角色判断就够

## 4. 性能观测建议

### 4.1 关键指标
- 文章详情接口耗时
- 搜索接口耗时
- Redis 命中率（建议在 `ArticleCacheManager` 加埋点）
- 监听器派发耗时

### 4.2 现有能力
- `/actuator/health` 暴露 MySQL / Redis 状态
- logback 输出到 `logs/pureblog.log` 与 `logs/pureblog-error.log`

### 4.3 建议补齐
- `@Around` 切面对 `*Service` 方法做耗时打点
- 线程池活跃线程数埋点
- JVM heap / GC pause 监控

## 5. 部署与运维

### 5.1 基础设施
- MySQL 8.0（宿主机端口 `13306`，容器内 `3306`，密码 `123456`）
- Redis 7
- JDK17 + Maven 构建容器（后端跑在容器内）

### 5.2 启动
- 根目录 `docker-compose.yml` 启动 MySQL + Redis + JDK17/Maven（唯一入口）
- 一键启动：`scripts\start-all.bat`；一键停止：`scripts\stop-all.bat`
- 后端 `mvn spring-boot:run` 或 `java -jar`
- 前端 `npm run dev`

### 5.3 日志
- 控制台 + 普通文件 + Error 单独文件
- 按天滚动，保留 30 天
- 单文件 100MB 触发滚动

## 6. 简历展示结论

> PureBlog 围绕文章发布链路、全文搜索链路、热点读取链路和目录树导航链路，在模块化单体中通过 Spring `ApplicationEventPublisher` 解耦通知生成与热度累加；Redis 承担热点缓存、PV/UV 与热度 ZSet；搜索基于 MySQL `LIKE` 多表 JOIN + 服务端转义高亮；目录树以物化路径 + 叶子校验支撑「知识图谱维度」的组织。整体展示缓存一致性与可观测能力。
