# 08 非功能需求与技术亮点

## 1. 非功能需求

### 1.1 性能目标
- 文章详情接口：缓存命中后 P95 < 200ms
- 文章列表接口：P95 < 300ms
- 搜索接口：P95 < 500ms
- 发布文章：主请求不等待 ES 同步与通知

### 1.2 可用性目标
- Redis 故障时允许回源数据库（`ArticleCacheManager` 缓存未命中走 MySQL）
- ES 同步失败不应回滚主事务（监听器内部 try-catch）
- 关键路径（详情 / 列表）任何异常都不应让接口 500

### 1.3 安全要求
- JWT 鉴权（accessToken + refreshToken）
- Token 黑名单（Redis 存储）
- Refresh Token 与用户绑定（Redis 存储）
- 评论 / 关注 / 点赞限流（**未实现，预留**）
- 密码 BCrypt
- 上传文件类型限制（**未实现**）

### 1.4 可维护性要求
- 模块化目录（`pureblog-xxx`）
- 统一响应 `ApiResponse<T>` / `PageResult<T>`
- 统一异常 `BusinessException` + `ErrorCode`
- 统一日志（logback-spring.xml）
- 统一事件定义（`pureblog-common` 的 `event/` 包）

## 2. 当前技术亮点

### 2.1 异步事件驱动
**亮点**：
- 文章发布后主事务只写 MySQL，索引同步通过 `Spring ApplicationEventPublisher` 派发
- 监听器（`SearchServiceImpl` / `NotificationEventListener` / `StatsEventListener`）解耦
- 监听器中的异常不会回滚主事务

**面试价值**：可以讲事务边界、事件分发、监听与重试。

### 2.2 Elasticsearch 全文检索
**亮点**：
- 标题（3.0）/ 标签（2.5）/ 摘要（2.0）/ 正文（1.0）加权
- 高亮字段 title / summary / content
- 支持 status=PUBLISHED 过滤
- 支持全量重建索引

**面试价值**：可以讲 mapping、权重、聚合、高亮、索引重建。

### 2.3 Redis 多场景
**亮点**：
- 文章详情缓存（字符串，TTL 30 分钟）
- 热门 ZSet（`pureblog:article:hot:zset`，score 实时累加 + 5 分钟兜底）
- PV 计数器（`INCR`）
- UV 集合（按 `yyyy-MM-dd` 维度）
- 用户资料缓存（字符串，TTL 30 分钟）
- 验证码 / 刷新 Token / 黑名单

**面试价值**：可以讲缓存 key 设计、TTL、缓存一致性、击穿/穿透/雪崩处理。

### 2.4 一致性策略
- 写 MySQL 后删除详情缓存（Cache Aside）
- 进程内事件驱动 ES 同步
- 不强求分布式事务，目标是最终一致

### 2.5 线程池与异步
- `AppConfig` 自定义 `ThreadPoolTaskExecutor`（核心 8，最大 16，队列 200）
- `@EnableAsync` + `@Async` 在监听器中显式标注
- 拒绝策略 `CallerRunsPolicy`，优雅关闭等待 60s

### 2.6 鉴权
- JWT accessToken + refreshToken 双 Token
- Refresh Token 存 Redis，可强制下线
- 退出登录通过黑名单实现（accessToken 加入 Redis）

### 2.7 仪表盘
- 实时聚合：总文章数 / 总用户数 / 总评论 / 总阅读
- 当日发布数
- 待审核评论数（**TODO 当前未实现**）

## 3. 不建议硬秀的点

以下功能当前并未实现，面试时被问"为什么没做"建议这样回答：

- ~~Kafka 异步消息~~：当前用进程内事件已足够，没必要引入额外中间件
- ~~微服务拆分~~：单体业务闭环还没做扎实，拆服务只是把复杂度转移
- ~~MinIO 文件存储~~：当前环境没启用，预留 `pb_file` 表
- ~~限流~~：当前单机单用户场景不构成压力，未做
- ~~链路追踪~~：单体阶段 APM 收益有限

## 4. 性能观测建议

### 4.1 关键指标
- 文章详情接口耗时
- 搜索接口耗时
- Redis 命中率（建议在 `ArticleCacheManager` 加埋点）
- 监听器派发耗时

### 4.2 现有能力
- `/actuator/health` 暴露 MySQL / Redis / ES 状态
- logback 输出到 `logs/pureblog.log` 与 `logs/pureblog-error.log`

### 4.3 建议补齐
- `@Around` 切面对 `*Service` 方法做耗时打点
- 线程池活跃线程数埋点
- JVM heap / GC pause 监控

## 5. 部署与运维

### 5.1 基础设施
- MySQL 8.0
- Redis 7
- Elasticsearch 8（中文分词推荐 `ik_max_word`）

### 5.2 启动
- `deploy/docker-compose.dev.yml` 启动 MySQL + Redis
- ES 单独启动（参考 README）
- 后端 `mvn spring-boot:run` 或 `java -jar`
- 前端 `npm run dev`

### 5.3 日志
- 控制台 + 普通文件 + Error 单独文件
- 按天滚动，保留 30 天
- 单文件 100MB 触发滚动

---

## 6. 简历展示结论

> PureBlog 围绕文章发布链路、全文搜索链路和热点读取链路，在模块化单体中通过 Spring `ApplicationEventPublisher` 解耦索引同步、通知生成与热度累加；Redis 承担热点缓存、PV/UV 与热度 ZSet；Elasticsearch 提供中文分词、加权与高亮检索。整体展示缓存一致性、最终一致性与可观测能力。
