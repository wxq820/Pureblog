# 01 技术栈与技术背景

## 1. 总体原则

技术选型要同时满足两件事：

1. 能支撑业务场景
2. 能体现你的技术深度

因此，本项目采用“核心必需 + 展示增强 + 可演进扩展”的三层技术栈设计。

---

## 2. 后端核心技术栈

### 2.1 Java 17
**用途：**
- 主开发语言
- 使用现代 Java 特性提升代码质量和表达力

**选型理由：**
- LTS 版本，稳定
- Spring Boot 3.x 原生适配更好
- 面试中也更容易说明现代 Java 实践

### 2.2 Spring Boot 3.x
**用途：**
- Web、IOC、AOP、事务、配置管理、整合中间件

**选型理由：**
- 开发效率高
- 生态成熟
- 适合做单体多模块与后续服务拆分

### 2.3 Spring MVC
**用途：**
- REST API 暴露

### 2.4 Spring Validation
**用途：**
- 参数校验，减少脏数据进入业务层

### 2.5 Spring Security + JWT
**用途：**
- 登录鉴权
- RBAC 权限控制

**为什么不用纯 Session：**
- JWT 更适合前后端分离
- 可结合 Redis 做 refresh token、黑名单、登录态控制
- 工程表达更现代

### 2.6 MyBatis-Plus
**用途：**
- 基础 CRUD
- 条件构造器
- 分页支持

**理由：**
- 个人项目效率高
- 基础表操作代码量小
- 复杂 SQL 仍可用 XML 精细控制

## 3. 数据存储与中间件

### 3.1 MySQL 8.0
**负责内容：**
- 用户、文章元数据、文章正文、标签、评论、通知、统计落库

**选型理由：**
- 博客核心数据属于典型关系型事务场景
- 易于建模，易于索引优化，易于事务控制

### 3.2 Redis 7.x
**负责内容：**
- 文章详情缓存
- 热门列表缓存
- 阅读量/PV 原子计数
- 验证码
- 限流计数
- Token 黑名单或 refresh token
- 防重复提交短期令牌

**为什么合理：**
博客是读多写少系统，Redis 能非常自然地带来收益。

### 3.3 Elasticsearch 8.x
**负责内容：**
- 文章标题、摘要、正文、标签的全文检索
- 搜索高亮
- 聚合分析
- 搜索排序

**为什么合理：**
如果没有搜索，这个项目只是管理系统；一旦加入 ES，项目层级会明显提升。

### 3.4 Kafka 3.x
**负责内容：**
- 文章发布事件
- 文章更新事件
- 文章删除事件
- 评论成功事件
- 通知事件
- 统计刷新事件

**为什么合理：**
发布文章后的 ES 索引同步、通知发送、热榜刷新都不应阻塞主事务。Kafka 在这里不是为了堆技术，而是为了解耦。

## 8. 关于 Dubbo 的态度

Dubbo **不建议作为第一阶段必需技术**，原因如下：

1. 博客项目在早期没有真实的跨服务治理压力
2. 一开始拆服务会显著增加复杂度
3. 面试时更容易被问“为什么不先模块化单体”

### 更合理的做法
- 第一阶段：单体多模块 + Kafka 异步事件
- 第二阶段：把搜索同步/通知做成独立服务
- 第三阶段：再引入 Dubbo 做服务间 RPC 演示

这样既保留展示面，也体现你有技术判断力。

## 9. 技术背景总结

这个项目真正想展示的不是“用了多少中间件”，而是：

- 我知道哪些技术值得用
- 我知道为什么用
- 我知道什么时候不该滥用
- 我能把业务闭环、工程实现、性能治理讲清楚

所以本项目的推荐技术重心是：

### 必须做深
- MySQL
- Redis
- Elasticsearch
- Kafka
- Spring Boot
- MyBatis-Plus
- JWT + Security
- 可观测性
- JVM 调优

### 可以增强
- MinIO
- 多级缓存
- 限流
- Outbox
- 幂等消费

### 可选演进
- Dubbo
- 服务注册发现
- K8s
- 链路追踪
