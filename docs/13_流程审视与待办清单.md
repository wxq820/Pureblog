# 13_流程审视与待办清单

> 目的：把整个项目按「浏览 → 登录 → 编辑 → 发布 → 挂到目录树 → 管理分类」的完整流程审视一遍，
> 找出阻塞、漏做或做得不到位的地方，给出整改方案。
> 适用对象：个人博客、不对外开放、计划部署到云平台、偶尔打开看看。
>
> 阅读建议：明天换电脑后先读第 1 节结论，然后按第 4 节的 P0 → P1 → P2 顺序逐项处理。

---

## 1. 一句话结论

工程表达力很强（事件驱动、缓存、索引、可观测），但**真正能让你"打开就看、写就发布"的核心链路断了 3 段**：

1. 树节点 → 该节点下的文章列表（前后端都没接通）
2. 图片上传（后端零上传接口，前端纯 textarea）
3. Markdown / 富文本编辑与渲染（无预览、无工具栏、无 MD 渲染库）

此外还有 5 个小坑，包括排序 bug、首页 tab 数据残留等。

## 2. 现状摸底

### 2.1 模块与代码分布

```
backend/
  pureblog-app        启动模块
  pureblog-common     响应、拦截器、枚举、工具、事件
  pureblog-auth       登录、注册、JWT、登录日志
  pureblog-user       用户资料、关注
  pureblog-article    文章、分类、标签、文章缓存、目录树挂载
  pureblog-comment    评论、点赞、收藏
  pureblog-search     ES 同步与查询
  pureblog-notification 站内通知
  pureblog-stats      PV/UV、热榜、仪表盘
  pureblog-admin      管理后台接口
  pureblog-tree       目录树（与分类是两个维度）
frontend/
  pureblog-portal     前台门户（Vue 3 + TS）
  pureblog-admin-web  管理后台（Vue 3 + TS + Element Plus）
deploy/
  docker-compose.dev.yml   只有 dev 配置，没有 prod
scripts/
  schema.sql / manage.ps1 等
docs/
  00 ~ 12 设计文档（本文为 13）
```

### 2.2 技术栈关键事实

- 异步事件用 Spring `ApplicationEventPublisher` + `@EventListener`，**没有 Kafka**。
  重启进程时未消费完的事件会丢，搜索索引需要重启后兜底重建。
- JWT 用 jjwt 0.12.6，刷新 token 接口存在（`/api/auth/refresh`）。
- 缓存：Redis 7 + 自定义 `RedisTemplate`。
- 搜索：Elasticsearch 8。

## 3. 流程审视（按用户视角）

### 3.1 浏览：看分类 / 看树 / 找文章

| 环节 | 现状 | 问题 |
|---|---|---|
| 首页热门/最新文章 | 正常 | — |
| 分类列表（左侧） | 正常加载，能跳到 `/?category=xxx` | URL 上的 category **没人 watch**，实际不会过滤右侧文章列表 |
| 目录树（中间） | 炫酷的 3D 旋转树，可点选叶子节点 | 选完之后**没有任何效果**——不跳、不加载、不写 URL |
| 树节点 → 文章列表 | **完全没接通** | 后端 DTO 没 `treeNodeId`，Service 没过滤，前端 SkillTree 选中后没动作 |
| 列表排序 | 写了 `orderByDesc(isTop).orderByDesc(viewCount).orderByDesc(publishedAt)` | MyBatis-Plus 后写的覆盖前面的，**前两个排序完全失效**，只剩 publishedAt |

**结论：树是个好看的视觉演示，还不是一个真正的导航入口。**

### 3.2 登录

> 个人博客、只用你一个人，所以**没有注册入口**。新账号直接在数据库 `pb_user` 表里 insert，
> 密码用 BCrypt 哈希（例如 hash 是 `$2a$10$...`）。前端登录页 `Login.vue` 也只保留登录表单。

| 环节 | 现状 | 问题 |
|---|---|---|
| 登录 | `Login.vue` 存在，调 `/api/auth/login` | — |
| 登录态持久化 | `stores/user.ts` + `composables/useUser.ts` 待确认 | 需验证 token 存 localStorage |
| 角色/权限 | 单人博客，无需复杂角色 | — |
| 后端 `/api/auth/register` 接口 | 代码保留 | 前端不再调用，浏览器无法触发 |

### 3.3 编辑文章

| 环节 | 现状 | 问题 |
|---|---|---|
| 编辑器 | 纯 `<textarea>` | 没有 MD / 富文本，没有工具栏，没有预览 |
| 自动保存草稿 | 无 | 误关页面丢稿 |
| 字数统计 | 后端存了，前端不显示 | — |
| 摘要 summary | DTO 有字段 | 前端没输入框，全靠手填 |
| htmlContent | 后端有字段 | 前端没生成，详情页如何渲染未确认 |
| **图片上传** | **后端零上传接口**（grep `MultipartFile` / `upload` / `oss` / `minio` 全部 0 命中） | **"插图片"完全做不了**，只能手填外链 URL |
| 分类选择 | `<select>` 加载 `getCategories` | 新分类无法在前台创建，得去后台或改库 |
| 树节点选择 | 两级 `<select>`，onTreeChange 重新拉树 | 切换每次都请求一次，没缓存 |
| 保存草稿 / 发布 | 两个按钮 | `saveDraft` 里同一个变量被检查两次（手抖 bug） |

### 3.4 发布 → 挂到目录树

| 环节 | 现状 | 问题 |
|---|---|---|
| 校验必须选叶子节点 | 后端 `treeService.assertIsLeaf` 强校验 | 好 |
| 切换分类时树节点未联动 | 分类 / 树完全独立 | UI 没体现"两个维度"的概念，容易困惑 |
| 写完树节点后计数 +1 | `treeService.incrementArticleCount` | 好 |
| 删除文章后计数 -1 | `treeService.decrementArticleCount` | 好 |
| 移动文章到别的叶子节点 | `updateArticle` 处理了 old/new 计数切换 | 好 |

### 3.5 管理分类 / 标签 / 树

| 环节 | 现状 | 问题 |
|---|---|---|
| 后端 CRUD | `CategoryTagController` 有 create/update/delete | 好 |
| Tree CRUD | `TreeAdminController` 有完整 CRUD | 好 |
| 前台管理 UI | 没有 | 个人博客可以接受，但前提是分类从一开始就想好 |
| 管理后台 UI | `pureblog-admin-web` 项目 | 是否真有"分类/标签/树"菜单待确认 |

### 3.6 部署 / 上云

| 环节 | 现状 | 问题 |
|---|---|---|
| 镜像化 | 没有 Dockerfile | 需要自己写 |
| 反向代理 / HTTPS | 没有 Nginx / Caddy 配置 | 需要自己写 |
| 生产 docker-compose | 只有 dev | 需要自己写 prod |
| 数据库备份 | 无 | 个人博客用云 RDS 自带，自建需要脚本 |
| Token 安全 | refresh token 已实现 | 是否黑名单 / 登出失效未确认 |
| 进程重启事件丢失 | 事件在进程内分发 | 搜索索引需要重启后跑一次 `rebuildSearchIndex` |
| `.gitignore` | 缺失 | `target/`、`logs/`、`.idea/` 已被 commit |

## 4. 待办清单（按优先级）

### 4.1 P0 — 不做就没法用

#### P0-1. 图片上传（后端 + 前端）

**后端**

新建 `pureblog-upload` 模块（或直接在 `pureblog-common` 里加 upload 工具 + 在 `pureblog-article` 里加 Controller）：

- 端点：`POST /api/upload/image`，接受 `multipart/form-data`，返回 `{ url, name, size }`
- 存储：先落本地 `./uploads/yyyyMM/xxx.{ext}`，返回 `/static/uploads/...` 相对路径
- 静态资源映射：`WebConfig`（或新建）注册 `addResourceHandlers("/static/uploads/**") -> file:./uploads/`
- 校验：白名单后缀（jpg/png/gif/webp）、大小限制（如 5MB）
- 安全：必须登录（用现有 `AuthInterceptor`）

后续要换 OSS / S3，只需替换存储实现，接口签名不变。

**前端**

- `ArticleEditor.vue` 加 `<input type="file">` 按钮 / 粘贴上传
- 上传成功后把返回的 URL 插入到 `content`（MD 语法 `![](url)`）和 `coverUrl`

#### P0-2. Markdown 编辑器 + 渲染

**前端依赖**

```json
{
  "dependencies": {
    "bytemd": "^1.x",
    "@bytemd/plugin-gfm": "^1.x",
    "@bytemd/plugin-highlight": "^1.x",
    "@bytemd/plugin-math": "^1.x",
    "@bytemd/plugin-medium-zoom": "^1.x",
    "highlight.js": "^1.x",
    "marked": "^1.x"
  }
}
```

**改造点**

- `ArticleEditor.vue` 用 `<Editor :value="form.content" @change="onContentChange" :plugins="plugins" />`
- 监听 `@change`，把 markdown 写到 `form.content`，**同时用 marked 同步生成 `form.htmlContent`**（后端已留字段）
- `ArticleDetail.vue` 渲染时直接用 `v-html="article.htmlContent"` + highlight.js 高亮
- 删除当前的 `<textarea class="content-textarea">`

#### P0-3. 树节点 → 文章列表（前后端打通）

**后端**

- `ArticleQueryDTO` 加字段：
  ```java
  private Long treeId;        // 树主表 ID
  private Long treeNodeId;    // 树叶子节点 ID
  ```
- `ArticleServiceImpl.getArticleList` 加过滤：
  ```java
  wrapper.eq(query.getTreeNodeId() != null, ArticleDO::getTreeNodeId, query.getTreeNodeId());
  wrapper.eq(query.getTreeId() != null, ArticleDO::getTreeId, query.getTreeId());
  ```
- 新增端点（可选，更清晰）：`GET /api/article/tree/{nodeId}?page=1&size=10`

**前端**

- `SkillTree.vue` 选中叶子节点后 `router.push({ query: { nodeId, treeId } })`
- `HomePage.vue` 加 `watch(() => route.query.nodeId, ...)`：
  - 清空 `articles`、重置 `page = 1`
  - 调 `articleApi.getList({ treeNodeId: ..., treeId: ..., page: 1 })`
  - 顶部显示"当前路径：Java / Java SE / 集合框架 / List"
- 注意：treeNodeId 必须是叶子（后端已强校验）

#### P0-4. 修排序 bug

`ArticleServiceImpl.getArticleList` 当前排序写法有问题，后写的覆盖前面的。

**改成单一 ORDER BY 链 + 复合优先级**（MySQL 自然行为是左优先）：

```java
// 置顶优先（强制第一个排序键）
wrapper.orderByDesc(ArticleDO::getIsTop);
if (StringUtils.equalsIgnoreCase(query.getSortBy(), "viewCount")) {
    wrapper.orderByDesc(ArticleDO::getViewCount);
} else if (StringUtils.equalsIgnoreCase(query.getSortBy(), "likeCount")) {
    wrapper.orderByDesc(ArticleDO::getLikeCount);
} else if (StringUtils.equalsIgnoreCase(query.getSortBy(), "commentCount")) {
    wrapper.orderByDesc(ArticleDO::getCommentCount);
} else if (StringUtils.equalsIgnoreCase(query.getSortOrder(), "asc")) {
    wrapper.orderByAsc(ArticleDO::getPublishedAt);
} else {
    wrapper.orderByDesc(ArticleDO::getPublishedAt);
}
```

### 4.3 P2 — 上云 / 长期维护

#### P2-1. Dockerfile + docker-compose.prod.yml

- 多阶段构建：`maven:3.9` 编 → `eclipse-temurin:17-jre` 跑
- 把 `uploads/` 挂成 volume
- MySQL 数据挂 volume
- Redis 密码化
- 环境变量管理 JWT 密钥、数据库密码等

#### P2-2. Nginx 反代 + HTTPS

- portal 5173 / admin 5174 / api 8080 统一收口到 80/443
- Let's Encrypt 证书
- 静态资源缓存策略（前端 dist 强缓存 1 年，HTML 不缓存）

#### P2-3. 数据库备份

```bash
# 每日 3 点 dump 到 /backup，挂对象存储同步
0 3 * * * mysqldump -uroot -p$DB_PASS pureblog | gzip > /backup/$(date +\%F).sql.gz
```

#### P2-4. Token 安全细节

- access token 短（如 2h），refresh token 长（如 30d）
- refresh token 存 Redis，登出 / 改密码时失效
- 校验 refresh token 一次性使用（旋转）

#### P2-5. 重启后搜索索引重建

- `pureblog-app` 启动后跑 `@PostConstruct` 一次性任务
- 列出所有 PUBLISHED 文章，逐个调 `articleService.rebuildSearchIndex`
- 加开关 `pureblog.search.rebuild-on-startup=false`，出问题可关

#### P2-6. 监控 / 健康检查

- Spring Actuator 已配（待确认）：`/actuator/health`、`/actuator/info`
- 加 `/api/article/ping` 给前端探活

## 5. 不需要做的（避免过度设计）

明确**不做**的事项，省得后面纠结：

| 不做 | 理由 |
|---|---|
| 引入 Kafka / RabbitMQ | 个人博客无跨服务事件分发需求，进程内事件够用 |
| 引入 ES 作为唯一搜索 | DB LIKE 也能顶住个人量级，ES 留着是为了表达工程能力 |
| 多用户角色权限矩阵 | 只有你一个写作者 |
| 评论系统完整审核流 | 个人博客，登录即可发 |
| 关注 / 通知 | 纯单人博客用不上 |
| 开放注册 | 单人博客，账号直接写库 |
| 管理后台 `pureblog-admin-web` 完整开发 | 数据库 / 命令行能改分类就够了 |
