# 12 简历表达建议

## 1. 项目一句话描述

> 基于 Spring Boot 3、MySQL、Redis、Elasticsearch 与 Spring 进程内事件驱动的模块化单体博客平台，围绕文章发布链路、全文搜索链路和热点读取链路，展示缓存一致性、最终一致性与可观测能力。

## 2. 可写进简历的要点

- 设计并实现文章发布、评论互动、站内通知、点赞收藏、热榜统计等完整业务闭环
- 基于 Redis 实现文章详情缓存、PV/UV 计数、热度 ZSet 排序，优化热点读取场景性能
- 基于 Spring `ApplicationEventPublisher` 解耦文章发布后的索引同步、通知生成与热度累加
- 基于 Elasticsearch 8 实现标题 / 摘要 / 正文 / 标签的全文检索、加权与高亮
- 设计 MySQL + Redis、MySQL + ES 的最终一致性方案，支持索引重建与缓存失效
- 通过统一异常 / 统一响应 / Logback 滚动日志完成工程化基础

## 5. 常被问到的问题与回答方向

### Q1: 为什么用 Spring 进程内事件而不是 Kafka？
A: 单仓单进程阶段，进程内事件足够支撑业务解耦；引入 Kafka 会增加运维成本（Broker、Zookeeper、副本、监控）。当前实现可以在不改动业务的前提下，替换为 Redis Stream 或 Kafka Outbox。

### Q2: Redis 缓存如何与 MySQL 保持一致？
A: 写完事务后删除详情缓存（Cache Aside）。对强实时性要求不高的列表，采用 DB + 短 TTL。计数器走 Redis 原子命令，不强制立即同步到 MySQL。

### Q3: ES 索引如何与 MySQL 同步？
A: 通过 `ArticleEvent` 监听器在事务后异步同步。删除 / 下线时同步删除 ES 文档。提供 `/api/search/index/rebuild` 全量重建能力。

### Q4: 为什么要自定义 AuthInterceptor 而不是用 Spring Security？
A: 当前项目鉴权需求简单（JWT + 拦截白名单），自定义拦截器更直观且代码量更少。Spring Security 仍保留做 CSRF / CORS 配置。

### Q5: 热度怎么算？
A: 实时通过浏览 +1、点赞 +10 累加 Redis ZSet score。每 5 分钟从 MySQL 全量刷新兜底。接口 `/api/stats/hot` 返回前 N。

### Q6: 鉴权怎么防 Token 泄露？
A: 双 Token 机制（accessToken 24h + refreshToken 7d）；refreshToken 存 Redis 可主动失效；accessToken 退出时进 Redis 黑名单。黑名单 TTL 与 accessToken 剩余有效期一致。

## 6. 简历项目描述模板

> **PureBlog**（个人项目 / 2024.01 - 至今）
>
> 基于 Spring Boot 3、MySQL、Redis、Elasticsearch 的模块化单体博客平台。围绕发布、搜索、热点读取三条核心链路，在不引入跨进程消息的前提下完成缓存与索引的最终一致性治理。
>
> **关键贡献**：
> - 设计并实现 10 个业务模块的鉴权、CRUD、审核、统计能力
> - 基于 Spring `ApplicationEventPublisher` + `@EventListener` 解耦发布后副作用
> - 基于 Elasticsearch 8 实现标题 / 摘要 / 正文 / 标签的加权全文检索与高亮
> - 通过 Redis 缓存 + 热度 ZSet + 定时刷新实现热点读取链路
> - 提供 Docker Compose 一键起 MySQL + Redis，5 分钟内可构建完整运行环境
