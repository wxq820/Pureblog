# 00 项目总览

## 1. 项目名称

PureBlog（中文名：纯粹博客）

## 2. 项目定位

**默认以个人技术博客为主**，同时代码层面保留多人协作能力（登录、注册、关注、通知、管理后台代码全在），部署时可按需启用。

> 文档立场统一：本文档的描述以「当前已落地的代码」为准。如果代码与文档不一致，改文档（详见 `.cursor/rules/docs-sync.mdc`）。

### 2.1 为什么是「个人博客」为主
- 实际部署目标：单账号、公开访问浏览、默认不开放注册
- 新账号直接在数据库 `pb_user` 表里 insert，密码 BCrypt 哈希
- 分类/标签/树等管理数据可在数据库或命令行维护，前端默认不暴露完整管理 UI

### 2.2 代码能力完整
- 后端完整实现：登录/注册/JWT、关注/通知、文章/分类/标签/树、评论/点赞/收藏、搜索、热榜、管理后台接口
- 前端门户（`pureblog-portal`）完整：首页/详情/搜索/登录/编辑器/通知/个人主页
- 前端管理后台（`pureblog-admin-web`）代码保留，按需启用

## 3. 核心业务目标

### 3.1 面向访客
- 浏览文章（列表、详情、热门、精选）
- 全文搜索（标题、摘要、正文、标签）
- 评论、回复、点赞、收藏
- 关注作者
- 接收站内通知

### 3.2 面向作者
- 写文章、保存草稿、发布文章、更新文章
- 上传封面图（通过 URL 字段或本地 `uploads/` 目录）
- 查看文章浏览/点赞/评论趋势
- 个人主页与个人文章

### 3.3 面向管理员（按需启用）
- 用户管理（修改角色、禁用账号）
- 评论审核（待审核、通过、拒绝）
- 文章管理（下架、删除）
- 分类、标签、目录树管理
- 仪表盘（总文章数、总用户数、待审核评论等）

## 4. 技术表达目标

本项目重点体现以下能力：

1. **关系型建模能力**  
   用户、文章、评论、关注、点赞、收藏、通知、目录树等数据模型设计
2. **缓存设计能力**  
   文章详情缓存、热门 ZSet 排序、PV/UV 计数器、Token 黑名单、限流基础
3. **异步架构能力**  
   通过 Spring `ApplicationEventPublisher` 解耦发布后副作用（索引同步、通知、热榜）
4. **搜索能力**  
   使用 Elasticsearch 8 + `co.elastic.clients` Java Client 实现全文检索、高亮、过滤、排序
5. **一致性治理能力**  
   MySQL 与 Redis、MySQL 与 ES 的一致性处理（删除缓存 + 事件同步）
6. **并发与性能能力**  
   `@EnableAsync` 异步任务、`ThreadPoolTaskExecutor` 线程池、Redis 原子计数
7. **工程化能力**  
   Docker Compose 多中间件、统一日志（logback-spring.xml）、统一异常、统一响应

## 5. 当前架构姿势

**模块化单体 + 进程内异步事件驱动**：

- 主请求同步写 MySQL
- 写完成后通过 `ApplicationEventPublisher.publishEvent(...)` 派发 `ArticleEvent`
- 搜索模块、通知模块、统计模块各自用 `@EventListener` 监听，做对应的副作用
- 没有跨进程消息中间件，没有微服务

这样的好处：
1. 一份 jar 跑所有业务，部署最小
2. 进程内事件性能高、零运维
3. 业务闭环完整后，将来想换 Kafka/RocketMQ，只需替换 publisher 与 listener 的实现

## 6. 项目角色

| 角色编码 | 含义 |
| --- | --- |
| 1 | 普通用户 |
| 2 | 作者 |
| 3 | 管理员 |
| 4 | 超级管理员 |

状态：`1` 正常 / `2` 禁用。

后台接口鉴权通过 `LoginUserHolder.get().isAdmin()` 校验（角色 3 或 4 通过），**未引入 RBAC**。

## 7. 核心模块

| 模块 | 职责 |
| --- | --- |
| pureblog-common | 通用响应、异常、事件、上下文、枚举、工具、Redis Key 常量 |
| pureblog-auth | 登录、JWT 过滤器、BCrypt、登录日志 |
| pureblog-user | 用户资料、关注关系、用户缓存 |
| pureblog-article | 文章 CRUD、分类标签、文章详情 Redis 缓存、ArticleEvent 发布 |
| pureblog-comment | 评论、点赞、收藏、文章统计、CommentCreatedEvent 发布 |
| pureblog-search | 全文检索、索引同步（监听 ArticleEvent） |
| pureblog-notification | 站内通知（监听 CommentCreatedEvent / FollowCreatedEvent / StatsLikeArticleEvent） |
| pureblog-stats | PV/UV、热榜、仪表盘（监听 StatsPvEvent / StatsLikeArticleEvent） |
| pureblog-tree | 目录树主表 + 节点 CRUD + 叶子校验 + 文章挂载计数 |
| pureblog-admin | 管理后台业务接口（用户/文章/评论/分类/标签） |
| pureblog-app | Spring Boot 启动、各模块装配、Redis/异步/调度配置 |

## 8. 实施策略

### 当前阶段（已落地）
- 后端模块化单体（11 个模块）
- 门户 + 管理台双前端（默认仅门户为主入口）
- MySQL + Redis + Elasticsearch
- 文章、评论、通知、统计、搜索、目录树完整闭环

### 后续可演进（不在当前计划内）
- 跨进程消息（Kafka / Redis Stream）替换进程内事件
- 文件存储 OSS / S3 替换本地 uploads
- 真正多级缓存（Caffeine + Redis）
- 限流与防刷
- 监控体系（Micrometer + Prometheus + Grafana）

## 9. 项目成功标准

- 发布文章后，主请求很快返回，索引/通知由 `@EventListener` 异步完成
- 搜索支持标题/摘要/正文/标签检索 + 高亮 + 过滤
- 热门文章读取优先走 Redis 缓存，缓存未命中回源 MySQL
- 文章更新后，缓存与索引能正确刷新
- 仪表盘可展示总文章数、总用户数、待审核评论数等关键指标
- 有 Docker Compose，可以一键起 MySQL + Redis + ES
- 目录树能作为文章组织的「第二个维度」，叶子节点挂文章且有计数
