# 00 项目总览

## 1. 项目名称

PureBlog（建议中文名：纯粹博客 / 技术博客平台）

## 2. 项目背景

这是一个为个人技术履历服务的博客项目。项目不追求“博客业务本身多复杂”，而追求：

- 业务场景真实
- 技术链路完整
- 中间件引入有明确理由
- 面试时能讲清楚每个技术点的价值与边界

因此，本项目不是简单的 CRUD 博客，而是一个具备工程表达力的内容平台。

## 3. 核心业务目标

### 面向普通访客
- 浏览文章
- 按分类、标签、作者搜索文章
- 查看热榜、最新文章、推荐文章
- 登录后评论、点赞、收藏、关注作者
- 接收站内通知

### 面向作者
- 写文章、保存草稿、发布文章、更新文章
- 上传封面和正文图片
- 查看文章浏览量、点赞量、评论量
- 管理个人主页与个人文章

### 面向管理员
- 审核评论
- 管理用户、角色、分类、标签
- 查看系统统计
- 处理违规文章或违规评论

## 4. 技术表达目标

本项目重点体现以下能力：

1. **关系型建模能力**  
   用户、文章、内容、标签、评论、通知、统计等数据模型设计

2. **缓存设计能力**  
   文章详情缓存、列表缓存、热点缓存、计数器、限流、防击穿

3. **异步架构能力**  
   文章发布后通过 Kafka 驱动搜索同步、通知发送、统计刷新

4. **搜索能力**  
   使用 Elasticsearch 实现全文检索、高亮、聚合、排序

5. **一致性治理能力**  
   MySQL 与 Redis、MySQL 与 ES、业务事件与消息投递的一致性

6. **并发与性能能力**  
   线程池、异步编排、热点更新、幂等消费、压测、JVM 调优

7. **工程化能力**  
   Docker Compose、本地多中间件环境、统一规范、监控与日志

## 5. 为什么博客适合做技术展示

博客虽然是通用业务，但天然具备几个非常适合展示后端能力的场景：

- **读多写少**：适合做缓存与热点优化
- **内容检索强需求**：适合引入 Elasticsearch
- **发布后有多个副作用**：适合引入 Kafka 做异步解耦
- **统计维度丰富**：适合做 PV/UV、热榜、行为事件分析
- **内容审核与权限存在层级**：适合设计状态机与 RBAC
- **文章内容大、访问路径长**：适合做 JVM 与性能观测

## 8. 实施策略

### 阶段一：先做完整闭环
- 后端单体多模块
- 前端门户 + 管理台
- MySQL + Redis + Kafka + ES
- 完成文章、评论、搜索、通知、统计

### 阶段二：增强技术深度
- Outbox 模式
- 幂等消费
- 压测脚本
- 可观测体系
- MinIO 文件上传

### 阶段三：服务化演进
- 将搜索同步与通知处理拆成独立服务
- 可选引入 Dubbo 进行 RPC 演示
- 增加服务注册与配置中心

## 9. 项目成功标准

如果下面这些都能展示出来，这个项目就已经足够强：

- 发布文章后，主请求很快返回，后续索引与通知异步完成
- 搜索支持标题/摘要/正文/标签检索与高亮
- 热门文章读取优先走缓存，缓存未命中回源数据库
- 文章更新后，缓存与索引能正确刷新
- 评论需要审核，审核状态清晰可控
- 统计数据可展示在作者后台和管理后台
- 有 Docker Compose，别人可以一键起整套环境
