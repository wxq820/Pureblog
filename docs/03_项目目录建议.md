## 5. 包设计原则

- 子模块按业务划分禁止跨模块直接访问 Mapper
- 跨模块调用通过 Service 接口
- 事件只通过 `ApplicationEventPublisher` 派发，避免反向依赖
- Controller 只做入参出参，不做业务
- 业务逻辑在 `Service` / `impl`
- 跨表 / 跨中间件逻辑封装在 `Manager`（如 `ArticleCacheManager`）
- 实体 `DO`、入参 `DTO`、出参 `VO` 严格分离

## 6. 命名规范

### 6.1 数据库表
- 前缀：`pb_`
- 全部小写 + 下划线
- 状态/类型字段用 TINYINT，对应枚举 `getCode()`

### 6.2 实体类
- `UserDO`、`ArticleDO`、`CommentDO`、`LikeDO`、`CollectDO`、`FollowDO`、`NotificationDO`、`LoginLogDO`
- 继承 `BaseDO`（含 `createdAt`、`updatedAt`、`deleted`）

### 6.3 DTO / VO
- 入参：`XxxCreateDTO`、`XxxUpdateDTO`、`XxxQueryDTO`
- 出参：`XxxDetailVO`、`XxxListVO`、`XxxVO`

### 6.4 Service / Manager
- `ArticleService` + `ArticleServiceImpl`
- `ArticleCacheManager`（跨中间件封装）

### 6.5 事件
- `XxxEvent`（record 或 class）
- 监听方法：`onXxx(XxxEvent)`

### 6.6 Redis Key
- 统一在 `RedisKey` 中定义
- 格式：`pureblog:业务:实体:{id}`（前缀 `pureblog:`）

## 7. 配置文件

```text
backend/pureblog-app/src/main/resources/
├── application.yml
├── application-dev.yml
└── logback-spring.xml
```

`application.yml` 是默认配置（容器名），`application-dev.yml` 是本地开发（localhost）。

通过 `spring.profiles.active=dev` 切换。

---

## 8. 目录约定总结

- **新模块** 必须放在 `backend/pureblog-xxx/`
- **新事件** 监听器放在对应副作用模块的 `listener/` 包
- **新 Redis Key** 在 `RedisKey` 中添加
- **新枚举** 放在 `pureblog-common` 的 `enums/` 包
- **新通用工具** 放在 `pureblog-common` 的 `utils/` 包
- **新接口** 入参用 `DTO`，出参用 `VO`，**禁止直接返回 `DO`**
