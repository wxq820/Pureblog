# 03 项目目录建议

## 1. 总体目录

建议使用单仓库（monorepo）管理，便于 Cursor 和你统一维护。

```text
pureblog/
├── backend/
│   ├── pureblog-app/
│   ├── pureblog-common/
│   ├── pureblog-auth/
│   ├── pureblog-user/
│   ├── pureblog-article/
│   ├── pureblog-comment/
│   ├── pureblog-search/
│   ├── pureblog-notification/
│   ├── pureblog-stats/
│   └── pureblog-admin/
├── frontend/
│   ├── pureblog-portal/
│   └── pureblog-admin-web/
├── docs/
├── deploy/
└── scripts/
```

## 2. 后端模块说明

## 2.1 pureblog-app
主启动模块，负责：
- Spring Boot 启动
- 组件装配
- 配置加载
- 扫描各业务模块

## 2.2 pureblog-common
公共模块，放：
- 通用响应结构
- 错误码
- 基础枚举
- 工具类
- 通用异常
- BaseDO / 审计字段
- 公共配置

## 2.3 pureblog-auth
放：
- 登录接口
- JWT 工具
- Security 配置
- 登录过滤器
- 鉴权逻辑

## 2.4 pureblog-user
放：
- 用户信息
- 作者主页
- 关注关系
- 用户设置

## 2.5 pureblog-article
放：
- 文章草稿 / 发布 / 更新 / 删除
- 分类标签
- 文章详情
- 文章版本
- 文章后台管理

## 2.6 pureblog-comment
放：
- 评论发布
- 评论回复
- 评论树
- 评论审核

## 2.7 pureblog-search
放：
- ES 文档模型
- 索引构建
- 搜索接口
- 索引重建任务

## 2.8 pureblog-notification
放：
- 站内信
- 评论通知
- 关注作者发布通知

## 2.9 pureblog-stats
放：
- 热榜计算
- 文章统计
- 仪表盘指标
- 行为事件处理

## 3. 单模块内部推荐结构

以 `pureblog-article` 为例：

```text
pureblog-article/
└── src/main/java/com/pureblog/article
    ├── controller
    ├── service
    │   ├── impl
    │   └── domain
    ├── manager
    ├── mapper
    ├── entity
    ├── dto
    ├── vo
    ├── convert
    ├── enums
    ├── event
    ├── consumer
    ├── config
    └── job
```

### 说明
- `controller`：接口层
- `service`：业务编排
- `manager`：跨表/跨缓存/跨中间件的复杂操作封装
- `mapper`：MyBatis-Plus / XML
- `entity`：数据库实体
- `dto`：入参对象
- `vo`：出参对象
- `convert`：实体转换
- `event`：领域事件定义
- `consumer`：Kafka 消费者
- `job`：定时任务

## 5. 包设计原则

- 包名按业务模块清晰划分
- 禁止所有逻辑都堆到 `serviceImpl`
- 禁止 `controller -> mapper` 直接穿透
- 跨模块访问通过 service / manager
- 中间件调用统一封装

## 6. 推荐命名规范

### 数据库表
使用前缀 `pb_`

### 实体类
- `UserDO`
- `ArticleDO`
- `CommentDO`

### DTO
- `ArticleCreateDTO`
- `ArticleUpdateDTO`
- `CommentCreateDTO`

### VO
- `ArticleDetailVO`
- `ArticlePageVO`

### Mapper
- `ArticleMapper`
- `CommentMapper`

### Service
- `ArticleService`
- `ArticleServiceImpl`

### Manager
- `ArticleCacheManager`
- `ArticleEventManager`
- `SearchIndexManager`

- Kafka
- Elasticsearch

- JWT
- ThreadPool

---

## 8. 目录建议结论

这套目录既能支撑单体多模块，又方便后续拆分，且对 Cursor 较友好。Cursor 生成代码时，按照模块和目录粒度实现，最不容易失控。
