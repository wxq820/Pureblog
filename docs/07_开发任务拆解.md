## 3. 明确不做（避免过度设计）

| 不做 | 理由 |
| --- | --- |
| 引入 Kafka / RabbitMQ / Redis Stream | 单仓单进程阶段进程内事件已足够；任何引入都要先更新 `docs/01`、`docs/02`、`docs/09` |
| 引入 Elasticsearch 等独立搜索引擎 | DB LIKE 也能顶住个人量级；独立引擎带来 512MB+ 常驻内存、索引一致性、冷启动等成本，收益不成正比 |
| 拆服务（search / notification 独立部署） | 当前无跨服务协作需求 |
| 多用户角色权限矩阵（RBAC） | 单一作者，admin 角色手动判断即可 |
| 评论完整审核流 | 当前直接 APPROVED，保留 PENDING 状态用于将来 |
| 关注 / 通知 | 代码完整但默认单人博客用不上 |
| 开放注册 | 单人博客，新账号直接写库 + BCrypt |
| 管理后台 `pureblog-admin-web` 完整 UI 开发 | 后台接口完整，前台默认不暴露菜单 |
