# 05 核心业务流程

## 1. 文章创建与发布

### 1.1 草稿保存流程

```text
作者填写文章
 -> 校验标题、分类、标签、正文
 -> 保存 pb_article(status=DRAFT)
 -> 保存 pb_article_content
 -> 保存 pb_article_tag
 -> 写入 pb_article_version(version_no=1)
 -> 返回草稿ID
```

### 1.2 发布流程

```text
作者点击发布
 -> 校验草稿是否完整
 -> 更新 pb_article.status = PUBLISHED
 -> 记录 publish_time
 -> 版本号+1
 -> 写版本快照
 -> 提交事务
 -> 发送 ArticlePublished 事件
```

### 1.3 发布后的异步动作
- 同步 ES 索引
- 给关注作者的用户生成通知
- 刷新热门文章候选集
- 更新首页最新文章缓存

---

## 2. 文章更新流程

```text
作者编辑文章
 -> 校验作者权限
 -> 更新 pb_article 元数据
 -> 更新 pb_article_content 正文
 -> 更新 pb_article_tag 标签
 -> 写入 pb_article_version
 -> 删除文章详情缓存
 -> 发送 ArticleUpdated 事件
```

### 异步动作
- 更新 ES 索引
- 刷新相关缓存
- 记录变更日志

---

## 3. 文章删除/下线流程

### 3.1 逻辑删除
```text
删除文章
 -> 校验作者或管理员权限
 -> 更新 status=DELETED / deleted=1
 -> 删除详情缓存
 -> 发送 ArticleDeleted 事件
```

### 3.2 下线
```text
下线文章
 -> 更新 status=OFFLINE
 -> 删除详情缓存
 -> 从搜索索引中移除或降权
```

---

## 4. 文章详情访问流程

```text
访问 /article/{id}
 -> 检查 Redis 详情缓存
    -> 命中：直接返回
    -> 未命中：查询 MySQL
 -> 查询文章元数据 + 正文 + 作者信息 + 标签 + 统计
 -> 组装详情 VO
 -> 写入 Redis
 -> 异步累加浏览量
```

### 注意点
- 文章详情缓存不要永久保存，建议 TTL 30 分钟 ~ 2 小时
- 对热门文章可以采用逻辑过期 + 后台刷新
- 对已下线/删除文章不能缓存正常态数据

---

## 5. 评论发布流程

```text
用户发表评论
 -> 登录校验
 -> 频率限制
 -> 内容校验
 -> 敏感词过滤
 -> 写 pb_comment(status=PENDING 或 APPROVED)
 -> 更新 comment_count（同步或异步）
 -> 发送 CommentCreated 事件
```

### 异步副作用
- 如果是回复评论，通知被回复用户
- 如果是普通评论，通知文章作者
- 更新文章评论计数
- 管理后台待审核计数刷新

---

## 6. 评论审核流程

```text
管理员查看待审核评论
 -> 审核通过：status=APPROVED
 -> 审核拒绝：status=REJECTED
 -> 若通过则进入前台展示
```

### 审核规则建议
- 可配置是否自动审核
- 普通用户默认走审核
- 管理员/白名单作者可免审

---

## 7. 搜索流程

```text
用户输入关键词
 -> 查询 ES
 -> 检索 title/summary/content/tags
 -> 按权重排序
 -> 返回高亮摘要
 -> 点击文章详情
```

### ES 文档建议字段
- articleId
- title
- summary
- content
- tags
- authorName
- categoryName
- status
- publishTime
- score

### 搜索权重建议
- title: 5
- tags: 3
- summary: 2
- content: 1

---

## 8. 热榜刷新流程

### 8.1 热度分建议公式
```text
score = 浏览量 * 0.4 + 点赞数 * 0.3 + 评论数 * 0.2 + 收藏数 * 0.1
```

可进一步引入时间衰减：
```text
hotScore = baseScore / (hoursSincePublish + 2)^0.5
```

### 8.2 刷新策略
- 定时任务每 5 分钟聚合一次
- 或收到行为事件时增量刷新
- 热榜结果写 Redis

---

## 9. 通知流程

### 9.1 关注作者后文章发布通知
```text
ArticlePublished 事件
 -> 查关注该作者的用户
 -> 批量生成 pb_notification
```

### 9.2 评论回复通知
```text
CommentCreated 事件
 -> 如果 reply_user_id 不为空
 -> 给被回复用户生成通知
```

---

## 10. 用户登录流程

```text
用户登录
 -> 查询用户
 -> 校验密码
 -> 校验状态
 -> 生成 access_token
 -> 生成 refresh_token（存 Redis）
 -> 记录登录日志
```

### 建议
- access_token 有效期较短
- refresh_token 存 Redis，支持失效控制
- 退出登录将 refresh_token 删除或将 JWT 加入黑名单

---

## 11. 缓存一致性流程

### 11.1 更新文章后
- 删除 `article:detail:{id}`
- 删除相关列表缓存
- 发送事件更新 ES

### 11.2 删除文章后
- 删除详情缓存
- 删除热榜缓存
- ES 删除文档

### 11.3 评论审核通过后
- 刷新文章评论树缓存
- 更新 comment_count

---

## 12. 索引重建流程

```text
管理员点击重建索引
 -> 分页读取已发布文章
 -> 批量组装 ES 文档
 -> 批量写入 ES
 -> 记录任务进度
```

### 适合展示的点
- 批量处理
- 分页扫描
- 线程池并行
- 失败重试
- 幂等重建

---

## 13. 流程设计结论

这个项目最该重点讲的不是“有多少功能页面”，而是三条链路：

1. 发布链路  
2. 搜索链路  
3. 热点读取链路  

只要这三条链路完整、稳定、可解释，这个项目就足够强。
