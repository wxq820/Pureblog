# 02 系统架构设计

## 1. 架构目标

本项目架构设计目标不是追求"服务越多越好"，而是：

- 先保证业务闭环可落地
- 通过事件驱动展示解耦能力
- 预留服务化拆分空间

因此推荐采用：

> **模块化单体 + 进程内事件驱动 + 可演进服务化**

---

## 2. 总体架构

```text
[Vue Portal]      [Vue Admin]
      \              /
       \            /
        ----[Nginx / Gateway]----
                 |
           [Spring Boot App]
                 |
   ---------------------------------------------------------------
   |       |        |       |      |       |        |       |
 [Auth] [User] [Article] [Comment] [Admin] [Stats] [Search] [Notify]
                 |        |                              |
                 |        |                              |
              MySQL     Redis          ApplicationEventPublisher
                                                  |
                              ---------------------------------
                              |               |               |
                  [SearchServiceImpl]  [NotificationListener] [StatsEventListener]
                              |               |               |
                        Elasticsearch    MySQL       Redis ZSet
```

### 关键点说明
- 主应用集中在一个 JVM，模块各自解耦
- 文章发布/评论/关注/点赞等都通过进程内事件通知到副作用模块
- 副作用模块之间互不感知，方便后续替换成远程消息

## 3. 模块划分

### 3.1 pureblog-common
**职责**：
- 统一响应 `ApiResponse<T>`、分页 `PageResult<T>`
- 统一异常 `BusinessException` + 全局处理
- 拦截器 `AuthInterceptor`
- 上下文 `LoginUser` / `LoginUserHolder`（ThreadLocal）
- 枚举：`UserRole`、`UserStatus`、`ArticleStatus`、`CommentStatus`、`NotificationType`、`FileType`、`ErrorCode`
- 事件定义（`event/` 包）
- Redis Key 常量（`RedisKey`）
- 工具类：`JsonUtils`、`StringUtils`、`WebUtils`、`IpUtils`、`DateUtils`

### 3.2 pureblog-auth
**职责**：
- 注册、登录、退出登录、刷新 Token
- 图形验证码
- BCrypt 密码
- JWT 颁发与解析
- 登录日志（`pb_login_log`）

### 3.3 pureblog-user
**职责**：
- 当前用户资料 / 他人主页
- 修改个人资料
- 关注 / 取消关注
- 粉丝列表 / 关注列表
- 用户信息缓存（Redis）

### 3.4 pureblog-article
**职责**：
- 文章创建（草稿）/ 更新 / 发布 / 下线 / 删除
- 文章列表 / 详情 / 热门 / 精选 / 作者文章
- 分类、标签 CRUD
- 文章详情缓存（`ArticleCacheManager`）
- PV 计数（Redis）
- 热门 ZSet 写入
- ArticleEvent 发布

### 3.5 pureblog-comment
**职责**：
- 评论创建 / 删除 / 评论树查询
- 评论点赞（`pb_like` 表 target_type=2）
- 文章点赞 / 取消点赞（target_type=1）
- 文章收藏 / 取消收藏
- 文章统计查询（点赞/收藏/评论 + 用户是否已点赞/收藏）
- 评论审核（管理员）
- CommentCreatedEvent 发布

### 3.6 pureblog-search
**职责**：
- ES 索引创建 / 重建
- 监听 ArticleEvent 自动同步索引
- 全文搜索（标题/摘要/正文/标签 高亮 + 过滤 + 排序）

### 3.7 pureblog-notification
**职责**：
- 监听 CommentCreatedEvent → 给文章作者 / 被回复人发通知
- 监听 FollowCreatedEvent → 给被关注者发通知
- 监听 StatsLikeArticleEvent → 给文章作者发通知
- 我的通知列表 / 标已读 / 全部已读 / 未读数

### 3.8 pureblog-stats
**职责**：
- 监听 StatsPvEvent → Redis 自增 PV + UV + 热度
- 监听 StatsLikeArticleEvent → 点赞热度
- 仪表盘数据聚合
- 热门文章（前 N）
- 作者文章热度
- `@Scheduled` 定时（5 分钟）从 MySQL 全量刷新热榜 ZSet

### 3.9 pureblog-admin
**职责**：
- 仪表盘
- 用户管理（列表 / 修改角色 / 禁用）
- 文章管理（列表 / 下架 / 删除）
- 评论审核（待审核 / 通过 / 拒绝 / 删除）
- 分类管理（创建 / 更新 / 删除）
- 标签管理（创建 / 更新 / 删除）

### 3.10 pureblog-app
**职责**：
- Spring Boot 启动入口
- `RedisConfig`（自定义 `RedisTemplate` 序列化）
- `AppConfig`（`ThreadPoolTaskExecutor` + `AsyncConfigurer`）
- `@MapperScan`、事务、异步、调度

## 4. 核心链路

### 4.1 文章发布链路

```text
作者点击发布
   -> @Transactional 开启
   -> 校验当前用户
   -> 更新 pb_article.status = PUBLISHED
   -> 记录 published_at
   -> 可能更新 is_featured / is_top
   -> 提交事务
   -> ArticleEventProducer.sendArticleEvent(ArticleEvent)
        -> 监听器 1：SearchServiceImpl#onArticleEvent -> 同步 ES 索引
   -> 缓存：evictArticleDetail + 维护 PV 计数器
   -> 维护用户 article_count、分类 article_count
```

> 注意：当前**NotificationEventListener 暂未监听 ArticleEvent**。  
> 关注通知的触发主要来自评论/点赞等行为，而非文章发布本身。

### 4.2 文章读取链路

```text
访问 /api/article/public/{id}
   -> ArticleCacheManager.getArticleDetail(id)
        -> 命中：incrementPv + 返回
        -> 未命中：查 MySQL
   -> 校验 status == PUBLISHED
   -> buildDetailVO 组装 VO（作者 / 分类 / 标签 / 统计）
   -> cacheArticleDetail(id, vo)，TTL 30 分钟
   -> incrementPv（Redis 计数器）
   -> 发送 ArticleEvent 给搜索/统计（可选）
```

### 4.3 搜索链路

```text
GET /api/search?keyword=...
   -> SearchServiceImpl.search
        -> ensureIndexExists
        -> 构造 BoolQuery：
             must:    title(3.0) / summary(2.0) / tagNames(2.5) / content(1.0)
             filter:  categoryId / tagId / status=PUBLISHED
        -> 高亮字段：title / summary / content
        -> 排序：relevance / viewCount / likeCount / publishedAt
        -> 返回 SearchResult（articles + total + page + tookMs）
```

### 4.4 评论链路

```text
POST /api/comment/create
   -> 校验用户
   -> 校验文章已发布 / 校验父评论
   -> 写 pb_comment（status=APPROVED，因为当前不做预审核）
   -> pb_article.comment_count + 1
   -> eventPublisher.publishEvent(CommentCreatedEvent)
        -> NotificationEventListener.onCommentCreated -> 通知作者或被回复人
```

### 4.5 点赞 / 收藏链路

```text
POST /api/article/like/{id}
   -> 查重，未重复则插入 pb_like
   -> pb_article.like_count + 1
   -> eventPublisher.publishEvent(StatsLikeArticleEvent)
        -> NotificationEventListener.onStatsLike -> 通知文章作者
        -> StatsEventListener.onLike -> Redis ZSet 热度 +10
```

## 5. 数据一致性策略

### 5.1 MySQL ↔ Redis
- 文章发布/更新/下线/删除 → `evictArticleDetail` 删除详情缓存
- 文章更新 → 不主动失效列表缓存（列表走 DB + 短 TTL）
- 关注变更 → 删除用户资料缓存
- 计数器走 Redis 原子命令，不强制立即入库

### 5.2 MySQL ↔ Elasticsearch
- 通过 `ArticleEvent` 同步
- 消费端（`SearchServiceImpl`）按 `eventType` 分发：
  - `PUBLISHED` / `REBUILD_INDEX` → 索引
  - `OFFLINE` / `DELETED` → 删除索引
- 提供 `/api/search/index/rebuild` 全量重建入口

### 5.3 业务与消息
- 当前进程内事件，事务提交后由 `ApplicationEventPublisher` 异步派发
- 监听器内的失败不会回滚主事务
- 若后续引入 Redis Stream / Kafka，建议补 Outbox 或消费幂等表

## 6. 缓存设计

### 6.1 文章详情缓存
- Key：`pureblog:article:detail:{id}`
- TTL：30 分钟
- 序列化：JSON（`JsonUtils`）

### 6.2 热门文章 ZSet
- Key：`pureblog:article:hot:zset`
- 写入时机：浏览 +1、点赞 +10
- TTL：7 天
- 兜底：每 5 分钟从 MySQL 全量刷新

### 6.3 PV 计数
- Key：`pureblog:article:pv:{id}`
- TTL：2 天
- 写入：详情接口命中或未命中时都 +1

### 6.4 UV 计数
- Key：`pureblog:article:uv:{id}:{yyyy-MM-dd}`
- Set 结构
- TTL：2 天

### 6.5 用户资料缓存
- Key：`pureblog:user:info:{id}`
- TTL：30 分钟
- 变更后失效

### 6.6 验证码 / Refresh Token / Token 黑名单
- 验证码：`pureblog:captcha:{key}`，TTL 5 分钟
- Refresh：`pureblog:refresh:token:{userId}`，TTL 7 天
- 黑名单：`pureblog:token:blacklist:{token}`，TTL = accessToken 剩余有效期

## 7. 安全设计

- 全局关闭 CSRF（前后端分离 + JWT）
- CORS 放行 dev 环境所有 origin
- 所有 `/api/**` 走 `AuthInterceptor`
- 白名单（`CommonWebConfig`）：
  - `/api/auth/**`
  - `/api/article/list`、`/api/article/hot`、`/api/article/featured`、`/api/article/author/**`、`/api/article/public/**`
  - `/api/search/**`
  - `/api/category/**`、`/api/tag/**`
  - `/api/user/public/**`
  - `/api/stats/**`
  - `/actuator/**`
- 业务权限校验：
  - 文章 CRUD 校验作者本人
  - 管理后台接口代码内通过 `LoginUserHolder.get().isAdmin()` 校验
- 密码：BCrypt，`DelegatingPasswordEncoder`

## 8. 演进路线（可选）

### 8.1 阶段二：可观测与限流
- 接入 Micrometer
- `/actuator/metrics` 暴露关键指标
- 关键接口加 `@RateLimiter` 注解

### 8.2 阶段三：跨进程消息
- 引入 Redis Stream 或 Kafka
- `ArticleEventProducer` 改发到 Redis Stream
- 监听器改为消费模式
- 引入消费幂等表

### 8.3 阶段四：服务化
- 拆 `pureblog-search` / `pureblog-notification` 为独立服务
- 引入 Spring Cloud OpenFeign 或 Dubbo
- 引入配置中心 / 注册中心

---

## 9. 架构结论

最推荐的说法：

> 我采用模块化单体完成博客业务闭环，进程内通过 Spring `ApplicationEventPublisher` 解耦发布后副作用（索引同步、通知、热榜刷新），保证主链路轻量；Redis 负责热点读取与计数器，ES 负责全文检索与高亮。后续如果需要跨进程协作，可以将事件 Publisher/Listener 平滑替换为 Redis Stream 或 Kafka，预留服务化演进空间。
